# WorkStore · 整体方案与设计规范 v0.1

> 实施更新：已接入 Tauri/Rust 并完成第一批本地基础功能，详见 [实现记录](实现记录.md)。下文的多工具文件协议与同步架构包含尚未落地的目标设计。

## 1. 定位与一期边界

一个本地优先、无需账号的轻量桌面工作平台，统一承载本地工具和 Web 工具。用户的工作目录是数据的最终归属，工具是访问数据的入口。

一期桌面系统：macOS、Windows、Linux。移动端仅预留领域层和存储协议，导航、文件权限、Git 后台运行需要另行适配，不把桌面布局直接缩放到手机。首版 AI 对话（app.ai）、项目（app.project）、文档（app.doc）均展示“开发中”，不暗示已提供业务能力。

当前交付含 React + Ant Design 6 界面、Tauri/Rust 桌面基础版、SVG 品牌图标和技术方案。桌面版已接入真实文件存储和目录选择；GitHub 同步和账号尚未接入。浏览器预览仍使用 localStorage 保存导航，与桌面数据独立。

## 2. 视觉方向

沿用参考图的左右布局：浅灰导航、白色内容区、清晰留白，强调工具本身。品牌主色为松石绿 #28796B；状态、交互集中使用这一强调色，各工具用低饱和色辅助识别。

应用图标使用圆角收纳盒与 W 字母组合，三个内部分隔代表工具，右上浅绿圆点代表就绪与灵感。SVG 是可编辑源文件；发布时从源文件生成 PNG、ICO、ICNS 及平台要求尺寸，并在 16/24/32px 检查辨识度。不得以彩色圆点单独传达状态，必须搭配文字。

## 3. 页面结构与交互

### 桌面壳层

- 左侧导航 260px，折叠为 72px；正式版允许 220–320px 拖拽调整。右侧填充剩余宽度。
- 顶部标题栏 58px。macOS 使用原生交通灯，折叠按钮放在其右侧；Windows/Linux 尊重系统窗口按钮位置，通常在右上角，不仿造 macOS 按钮。原型中的交通灯仅为视觉示意。
- “WorkStore”品牌按钮回到工作台；右侧按钮固定命名为“打开工具”。采用浅灰胶囊样式，左侧工具图标、右侧向下箭头。点击弹出目录 Modal；⌘K / Ctrl+K 同样打开。
- 常用条目直接显示，不设标题栏；最近分组命名为“最近”，空列表只显示“暂无”；底部只保留设置。导航独立滚动，底部设置始终可达。图标折叠后保留工具提示。
- 初始右侧工作台展示常用入口、实用工具与本地数据说明；打开工具后在同一右侧容器切换，不无限创建标签页。

导航条目高度 32px，条目间距 1px，图标与文字间距 7px。移除右侧全局面包屑栏；工具页不再提供“切换工具”按钮。单页工具不显示 Tab，所有工具共用 ToolHeader 的可选 Tab 与操作插槽。

### 唯一集合与派生列表

工具注册表和用户导航状态分别存储。用户状态按 toolId 唯一：

```ts
type UserToolState = {
  toolId: string;
  favorite: boolean;
  favoriteOrder: number;
  lastOpenedAt: string | null;
};
// 常用：favorite === true，按 favoriteOrder 排序
// 最近：favorite === false && lastOpenedAt !== null，按时间倒序
```

打开工具时 upsert 时间，始终先用 toolId 查重。已常用的工具只高亮常用条目，正式版在列表溢出时滚动到该项。最近条目可拖入常用；下拉“设为常用”作为等效键盘操作。原型支持拖入但暂不支持常用列表内部排序，正式版通过拖拽或“上移/下移”调整。

最近的“…”菜单包含“设为常用”“删除记录”。删除仅移除导航记录，不删工作文件、不卸载工具；如果删除当前最近项，回到工作台。常用菜单提供“取消常用”，取消后进入最近。无使用记录的默认常用在取消时记录当下时间，保证条目可找回。最近为空时显示说明，不用演示记录伪装真实使用历史。

Modal 显示工具图标、名称、描述、本地/Web、开发状态；支持搜索名称、描述、ID，分类筛选、无结果提示、ESC 关闭和关闭后焦点返回。未开发的工具仍可打开至占位页，导航标记“开发中”。不使用看似可用却无反馈的入口。

### 设置

1. 通用：工作目录、目录选择、迁移状态、导航重置。
2. GitHub 同步：默认关闭，仓库、分支、认证方式、同步范围、最近成功时间、重试与冲突入口。
3. 关于：版本、图标、未来诊断入口。

首次连接同步应在明确展示范围后启用；日常成功自动同步不弹窗。离线显示低干扰状态，认证失败或冲突展示可操作提示。“无感知”指正常路径安静，不表示失败不可见。

## 4. 技术选型

| 层       | 建议                                 | 原因与边界                                                    |
| -------- | ------------------------------------ | ------------------------------------------------------------- |
| 桌面容器 | Tauri 2                              | 复用系统 WebView，降低随包引擎体积；仍需测试三端 WebView 差异 |
| 本地服务 | Rust + Tokio                         | 文件读写、目录监听、同步队列、后台任务，避免阻塞 UI           |
| UI       | React 19 + TypeScript + Ant Design 6 | 统一 Modal、菜单、表单、提示等基础组件，主题 token 定制       |
| 构建     | Vite                                 | 静态资源打包，工具路由懒加载，不内嵌 Node 服务                |
| 状态     | React 状态起步，复杂后引入小型 store | 避免为简单壳层引入过多运行时依赖                              |
| 持久化   | JSON + Markdown + 原始附件           | 文件为事实来源，不依赖服务端数据库                            |
| 可选同步 | 系统 Git 命令行                      | 复用 SSH Agent / Git credential helper；未安装 Git 只影响同步 |

Tauri 官方说明其不随应用打包 WebView；这有利于体积，但 Windows WebView2 或 Linux WebKitGTK 的安装与兼容性不能忽略。Ant Design 6 支持 React >=18，计划使用 React 19。版本锁定以仓库 package-lock.json 和构建验证为准。

## 5. 模块架构

```text
原生窗口 / 系统菜单
└─ React Shell
   ├─ WorkspaceHome / Navigation / ToolCatalog / Settings
   ├─ ToolHost → 内置受信任的本地工具 React 模块
   └─ RemoteToolHost → 独立隔离 WebView（无本地 IPC 权限）
        ↓ 类型化命令 / 事件
   Rust Core
   ├─ WorkspaceService：定位、初始化、目录迁移、文件锁
   ├─ FileStore：路径约束、原子写、版本迁移、备份
   ├─ ToolRegistry：注册信息、schema、工具生命周期
   ├─ TaskService：取消、进度、超时、资源预算
   ├─ SyncService：Git、队列、重试、冲突
   └─ IdentityPort：LocalIdentity，未来可接 AccountIdentity
```

工具通过受限 API 访问自己的 data/<toolId>，不直接调用任意磁盘路径。命令使用结构化参数，不把工具输入拼接成 shell。规范化路径后拒绝目录逃逸和符号链接越界。

工具注册结构预留：id、name、version、kind(local/web)、icon、description、entry、capabilities、dataSchemaVersion、availability。首版仅内置审核过的模块，不支持用户下载任意 JS/Rust 插件。热安装和插件签名另立后续阶段。

Web 工具不能统一假设 iframe 可嵌入，站点可能限制嵌入或登录。正式版采用隔离 WebView，并对 macOS/Windows/Linux 验证子视图定位、缩放、IME 与登录流程；不兼容时使用独立受限窗口或系统浏览器。弹窗、新窗口、下载和导航由宿主处理；远程视图不继承本地文件命令权限。原型仅示范用系统浏览器打开 GitHub。

## 6. 文件存储

默认工作目录为系统应用本地数据目录下 workspace；首次启动验证可写性，可通过系统选择器更改。旧默认文稿目录自动复制迁移并保留源文件，自选目录保持不变。默认日常读写不依赖文稿目录权限。

```text
~/WorkStore/
  workspace.json                  # UUID、schemaVersion、名称
  preferences/
    tools/<toolId>.json            # 每工具常用状态、排序，便于合并
  data/
    app.ai/conversations/<id>.json
    app.project/projects/<id>.json
    app.doc/documents/<id>.md
    <toolId>/...
  assets/<content-hash>.<ext>      # 内容寻址附件
  .workstore/
    devices/<deviceId>/recent.json # 每设备最近列表（默认不同步）
    cache/                        # 可删除并重建
    logs/                         # 轮转日志，不保存密钥
    conflicts/                    # 本地冲突副本
    backups/                      # 恢复用备份
  .gitignore
  .git/                           # 仅启用同步时存在
```

工作目录指针放在系统 app config 目录的 bootstrap.json，启动最大化等机器级偏好单独放在 preferences.json。机器级绝对路径、缓存、最近历史、日志、冲突备份默认排除 Git；同步工作内容和常用偏好。后续可显式选择是否共享最近记录。

文件写入：schema 校验 → 同目录临时文件 → flush/fsync → 原子替换；目录适用时同步目录元数据。不同系统的替换/占用行为由平台适配处理。单实例/进程锁避免两个应用同时写同一工作空间；外部编辑通过监听、防抖、内容哈希识别，不能产生循环写入。文件迁移前备份，schemaVersion 不兼容时只读提示。

更换目录：暂停写入/同步 → 检测权限、空间、目标冲突 → 复制到暂存目录 → 校验清单和哈希 → 原子更新指针 → 重开工作空间。跨磁盘不依赖 rename 原子性；失败回到原路径，保留旧目录，成功后也不自动删除旧数据。

严格文件存储与凭据：Git 凭据由用户现有 SSH Agent 或 Git credential helper 管理，WorkStore 不落盘令牌。此处外部系统凭据不属于工作空间业务存储；若以后引入 API 密钥，在明确设计加密文件及密钥保管方案前不以明文写入 JSON 或 Git。

## 7. 可选 GitHub 同步设计

Git 是版本与同步通道，不是实时协作数据库。第一期只支持专用数据仓库，不对用户代码仓库执行自动 add/commit。首次连接验证 Git、remote、分支、认证、工作目录边界和现有文件；远端已有数据时提供导入/合并流程，不覆盖本地。

```text
Disabled → Idle → Debouncing → Committing → Fetching → Merging → Pushing → Idle
                                     ↘ Offline / AuthRequired / Conflict / Error
```

本地写入约 5 秒防抖，后台单队列串行提交。使用明确允许的路径列表暂存，禁用 hook 执行，不传递 shell 文本；fetch 后检查分叉，在本地无并发写入的快照上合并；成功再 push。远端推进导致 push 拒绝时重拉并有限重试，绝不 force push。同步进程崩溃时可从 journal 恢复，不创建一串临时用户可见提交。

多设备同文件变更：JSON 可按不同字段三方合并；同字段变更、Markdown 重叠段、二进制冲突不使用“最后时间戳胜出”。保留 base/local/remote 副本，标记工具与文件，暂停相关推送，用户可选保留某方或合并。删除与修改同时发生也视为冲突。设备时钟用于展示而非冲突胜负裁决。

网络失败指数退避并带抖动；认证失败停止自动重试并提供修复入口。退出时不等待无限网络请求，下次启动续传；“后台”仅指应用运行时，用户彻底退出后不承诺常驻同步。关闭同步保留本地数据和 Git 历史，清除后台任务。

默认排除缓存、日志、凭据和临时文件；大附件在纳入前检测大小和仓库策略，普通 Git 不适合作为无限媒体盘。一期对大文件跳过并提示，Git LFS 作为显式后续选项。

## 8. 统一工具设计规范

| 项目         | 约定                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 页面分区     | 统一标题栏：左侧小图标、标题与同排小字描述；中间可选多页面 Tab；右侧功能按钮；下方主内容区                |
| 主操作       | 每视图一个最显著的主按钮，例如“格式化”；次操作用描边或文本                       |
| 间距         | 4px 基准，8/12/16/24/32/48；内容区通常 32–48px 外边距                            |
| 字体         | 系统无衬线；正式工具正文 14px，辅助 12px，标题 20–28px；代码使用等宽             |
| 颜色         | 主色 #28796B，正文 #252C2B，边框 #E4E8E6；原型浅色微文案上线前做对比度加深       |
| 圆角         | 控件 8px，卡片 12px，Modal 18px；避免页面堆叠过多阴影                            |
| 图标         | 品牌单独 SVG；工具/动作统一线性图标，16/20/24px，必须有可访问名称                |
| 状态         | loading、empty、success、error、offline、permission-denied、development 完整覆盖 |
| 保存         | 内容编辑自动保存，显示“保存中/已保存/失败”；失败保留输入并允许重试               |
| 危险操作     | “删除记录”和“删除文件”明确区分；记录移除可撤销，真实数据删除进入回收区           |
| 快捷键       | ⌘/Ctrl+K 打开工具，Escape 关闭浮层；不得覆盖编辑器常用快捷键                     |
| 键盘与无障碍 | 可见焦点、合理 Tab 顺序、工具名 aria-label、拖拽等效菜单、关闭弹窗归还焦点       |
| 动效         | 120–180ms 轻微变化；遵从 reduced-motion；不做持续装饰动画                        |
| 多端         | 桌面最小建议 960×640；窄宽度折叠侧栏、工具卡片改列；移动端独立设计               |

正式主题 token 应由共享包导出，工具禁止复制一套自己的菜单、Modal、保存提示。原型先验证结构和视觉方向，生产验收需要 WCAG AA 对比度、键盘和屏幕阅读器检查。

## 9. 身份预留

当前 workspaceId 与 deviceId 独立，owner 使用 local 身份。业务服务只依赖 IdentityPort，不让工具依赖登录态；未来账户、授权、远程连接可新增 provider。登录后关联已有工作空间，不改文件 ID，也不强制把用户文件搬到厂商服务器。GitHub 仓库认证与 WorkStore 用户身份是两件独立的事。

## 10. 性能目标与验证

设计目标（未实测承诺）：常用工具切换 <100ms、热启动交互就绪 <1s、冷启动 <2s、交互 p95 <100ms；基线机器为现代 4 核/8GB RAM/SSD。安装包目标 <30MB，不含系统 WebView 安装依赖；空闲内存总进程目标 <180MB。三端分别记录，不用壳层 Rust 进程内存代替总内存。

工具按路由懒加载；远程 WebView 按需创建并回收；图片缩略图缓存有上限；长任务交给 Rust 工作线程；文件监听按目录聚合；工具搜索先内存索引；大列表虚拟化。性能未达标时用启动 trace、bundle 报告和系统进程测量定位，再决定是否更换组件。

## 11. 落地顺序与验收

1. 设计确认：导航宽度、视觉、图标、Modal 和占位页面。本仓库覆盖此阶段。
2. 原生壳层：Tauri 三端窗口行为、工作目录服务、原子保存、唯一导航集合与工具注册。
3. 工具标准：统一宿主、状态/错误/权限组件，本地工具交互、WebView 隔离。
4. 可选同步：专用测试仓库覆盖离线、多设备分叉、认证过期、并发写入、崩溃恢复和大文件策略。
5. 分发：三端构建、macOS 签名/公证、Windows 签名、Linux 包格式、签名更新包与回滚验证。

验收重点：常用与最近零重复；最近拖入常用立即消失于最近；目录迁移失败文件不丢；无 Git 时全部本地功能可用；同步冲突不覆盖；远程网页无法调用磁盘命令；不登录即可完成一期完整流程。
