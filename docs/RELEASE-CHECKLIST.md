# WorkStore 发布规则

正式软件发布必须使用 `npm run desktop:release:build`，本机更新使用同一入口的本机模式。完整实验包不作为正式版。规则保存在 AGENTS.md、src/release-manifest.json 和可执行检查脚本中。

1. 核对工具范围：当前开放记笔记、画白板、做封面、设计室、画漫画、做课程。实际输出必须有全部课程页面；隐藏工具页面不得漏入。
2. 图片和媒体只按有效目录引用发布。封面大预览、设计室素材、课程117项参考资源与试听、四类可选运行组件按固定版本获取并缓存，不能复制全目录或打回软件包。原图、源资料、用户文件保留；公共素材不能包含用户作品或凭据。
3. 资源发布后核对全部 Git blob 或 Release 附件的大小/SHA-256，签名软件内嵌固定版本索引。客户端下载完整性校验通过才返回文件，断网复用有效缓存；损坏缓存重试。组件还验证内部文件权限与哈希，再按需解包、启动；下载、校验、解包在后台完成，不持有工作区写锁。
4. `npm run release:check` 必须通过：版本五处一致、原更新公钥不变、固定索引匹配源图、白名单与预算正确。正式构建自动执行完整前端和单线程Rust回归，默认不运行外部模型/联网测试。
5. 前端不超过80MiB，macOS应用不超过90MiB；Resources只允许应用图标。缺图、额外资源、隐藏模块、缺少正式页面、超预算阻断构建，不能通过放宽检查绕过。
6. 校验应用签名、更新包签名与可信注释、DMG完整性。正常退出旧应用，保留旧包；新安装、更新包和DMG内应用全部文件/链接的哈希及权限必须一致。原生验证课程四类入口、图片/视频/网页预览及原文稿恢复。
7. 从验收源码新建不可变版本标签，创建Release草稿，上传并核对全部安装/更新附件，完整后才设为Latest。资源Release为独立固定版本的预发布，不进入软件稳定更新通道；旧版本不得改写。

课程知识卡片与交互网页可直接使用；首次试听、预览未缓存媒体需要联网。视频制作首次准备Node、渲染器及需要的Python/配音组件，网页在线发布才准备发布服务；这些缓存会增加设备占用，与轻量安装包及用户作品分开。当前课程组件仅验证macOS Apple Silicon。无网络且组件尚未准备时，保留已保存作品并明确提示重试，不要求用户安装开发环境。
