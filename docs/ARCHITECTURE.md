# 架构与稳定决定

## 分层

React / Ant Design 提供容器和子应用 UI；`src/workspace.ts` 协调保存、后台同步与刷新；Tauri 命令进入 Rust 文件存储和系统能力。

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 主容器 | `src/main.tsx`、`src/navigation.ts` | 导航、工具入口、设置、稳定的最近顺序 |
| 文件存储 | `src-tauri/src/storage.rs` | 原子写入、工作区锁、备份、外部改动检测、目录迁移 |
| 生命周期 | `src/documentLifecycle.ts` | 文档保存注册，退出、切换、同步前刷新保存队列 |
| 数据同步 | `src/workspace.ts`、`src-tauri/src/sync.rs` | 后台 Git 传输、三方合并、激活、列表刷新 |
| 文档/白板/漫画 | `src/documents/`、`src/whiteboard/`、`src/comics/` | 独立文件、缓存、版本 token、延迟保存 |
| AI | `src/ai/`、`src-tauri/src/ai.rs`、`ai_images.rs` | provider 路由、设备配置、取消/超时和图像能力 |
| 更新 | `src/updateService.ts`、`scripts/*update*.mjs` | 签名清单、下载、安装与重启 |
| 模板目录 | `content/comics/`、`schemas/` | 版本化公开模板与校验，不是用户漫画数据 |

## 默认入口与工具精简

应用默认进入项目，WorkStore 品牌与导航回退均指向项目，不提供首页。AI 对话、JSON 工具、时间工具不再注册或显示；旧工作区的兼容字段与历史工具记录保留，渲染时过滤，避免破坏存量数据与旧版同步。子工具的统一 AI 能力不受独立 AI 对话入口移除影响。原生图标源为 `src-tauri/icons/app-source.svg`，图形占画布 84%，可用 Tauri icon 命令重新生成平台图标。

## 主导航隐藏布局

主导航隐藏时完全让出宽度，不展示 dock。容器提供紧凑工具标题栏，包含展开主导航、WorkStore 品牌、“打开工具”弹窗入口、横向常用/最近工具列表、更新和设置入口；工具切换复用现有保存与导航流程。横向列表复用同一集合及顺序，当前工具高亮，空间不足时单行横向滚动，键盘聚焦的条目滚动进入可见区域。各工具标题不显示描述，工具自身的文档列表可独立折叠。macOS 原生窗口预留系统窗口按钮位置；隐藏/展开主导航不更换编辑器组件或文档 key。更新自动检查只由常驻入口调度，紧凑栏共享状态。

## 桌面窗口与首击

- Tauri 平台配置按 JSON Merge Patch 合并，`app.windows` 数组会整体替换，而不是按窗口 label 继承。macOS 主窗口必须显式保留 `acceptFirstMouse: true` 和 `dragDropEnabled: false`：非激活窗口的首击应到达 WebView，工具内拖动由网页处理。
- 应用启动与配置回归测试共用 `application_context()`，验证的是平台合并后的真实 Tauri 配置，不只检查基础 JSON。
- 同步等待不能只判断文本框是否失焦；`focusout` 可能处于 `pointerdown` 与 `click` 之间。全局被动观察按下的指针、按键与操作结束后的短暂空闲期，待完整操作结束再开始激活；取消、拖动结束和窗口失焦要释放悬挂状态。不得吞掉、合成或重放用户点击来补救，否则可能重复执行操作。

## 文档选择与异步载入

2026-09-20 用户确认文档首击修复有效；事件证据、适用边界、排查误区与回归要求见[经验记录](lessons/document-first-click.md)。下述按下选择仅适用于文档列表，不是通用按钮规范。

- 文档名称/行空白的无修饰主鼠标左键使用捕获阶段的 `pointerdown` 接受选择，阻止默认焦点转移，不依赖可能在编辑器失焦后丢失的 click。仅改变文档列表的选择语义，不模拟/重放点击；仍先保存，成功后才载入和提交选中状态，正常后续 click 去重。触控/笔输入继续等 click，拖拽图标、辅助键点击和右键不走此快捷路径，键盘/辅助技术 click 保留。
- 输入法组合期间暂存最新选择，允许平台完成组合，待 compositionend 后最后的 input/update 到达，再保存并切换。新组合开始或组件卸载须取消过期的结束定时器；待选择期间继续保护同步激活。
- 已显示的文档列表不能因初始化、保存或载入而整体 disabled；点击表示最新选择意图，待载入项使用独立状态提示。切换遮罩必须限制在相对定位的编辑工作区，不能盖住文档列表或主导航。
- TeaEditor 的 `.ContentEditable__root` 直接父容器保持 block，不能改成 flex/inline-flex；Lexical 对这一布局有明确的点击外部焦点异常告警。填满高度通过外层 flex 和内层高度控制，不让 contenteditable 成为直接 flex 子项。布局回归使用真实 Lexical，而非仅用编辑器替身。
- 初始自动打开、用户切换与创建共用请求版本，只有最新且仍挂载的请求才能提交选中文档、错误提示和 loading 状态。再次点击当前文档可以取消未完成的切换；创建已经完成的文件必须保留，但不能抢回用户后续选择。
- 数据载入与激活分离：读取/创建只准备文件和缓存，确认请求有效后才更新 `lastDocumentId`。异步读取须比对缓存对象、generation 和 token，不能覆盖读取期间新增或已保存的编辑；取消回当前文档时不重载正在使用的编辑器缓存。
- 文档选择未完成时注册同步激活保护，仍允许本地保存；只有当前选择结束或组件卸载才解除保护。保存失败保持原文档，不强行切走。

## Git 数据同步

工作目录文件是源数据；私有 checkout 只用于 Git 网络传输。应用定时及在启动、窗口恢复、联网、本地保存后检查远端。网络阶段允许编辑，激活阶段短暂串行化写入和刷新。

- 使用共同基线做三方合并，导航成员按工具 ID 合并；不能随意把编辑器数组拆开合并。
- 冲突不生成新的可见文档 ID。独立 JSON 字段自动合并，导航按工具 ID 合并；同一不可分割正文/数组重叠时保留已同步的远端值（不依赖设备时钟），把基线、本地、远端原字节写入 `.workstore-history/sync/`。历史使用内容哈希命名、完整性校验、Base64 无损编码，随 Git 同步且追加保留，不进入文档/白板/漫画列表；不把 Git 文本冲突标记写入 JSON。
- 新设备合并已有本地内容，不用空的初始化数据覆盖远端。`.workstore-history/` 是用户工作区的同步历史，与源码仓库及排除同步的 `.workstore/` 私有缓存不同。
- 旧可见副本只在类型、创建时间、截断标题能唯一匹配原文件，或已有有效历史映射时整理；无法唯一归属的文件保留，不能仅凭标题删除。先把副本全部原字节和原路径归档，再移出工具目录，主文件不改；归档映射防止老设备回传已整理副本时重新出现在列表，新编辑也先归档。
- 旧副本整理在启动、界面尚未挂载且工作区锁已取得时进行；网络准备阶段只改传输缓存，激活时根据最新保存快照归档。多文件整理写恢复日志，先落历史文件再移除可见副本，保留共同基线用于下一轮同步。离线维护命令必须取得同一个独占工作区锁，否则拒绝修改。
- 网络期间保存的本地改动保持优先，后续循环再同步。
- 文本输入或编辑器注册的文本会话尚未结束时，延后同步激活和界面刷新，不能用 `body.inert` 强制打断输入；Excalidraw 失焦会提交并销毁文本框，事后恢复 focus 不能补救。等待期间不持有工作区锁，本地自动保存继续；编辑结束后重新刷新保存队列，再短暂保护激活与列表刷新。
- 等待激活期间产生的保存请求必须合并为后续同步，不能因复用进行中的同步 Promise 而丢失。安装更新可唤醒并取消编辑等待，避免等待输入结束阻塞更新；未应用的结果由恢复后的新同步重新准备。
- 刷新一个工具失败不得阻止其他工具；未变化的拉取也补刷列表，保留待重试路径。
- `.workstore/` 不参与传输。残留 Git 锁时选择新的缓存代次，保留旧缓存和工作区基线，不盲目删锁。
- Git 网络操作自动读取系统代理；当前 macOS 从系统 HTTPS 代理读取，其他平台继承代理环境变量。fetch/push 总限时 300 秒，ls-remote 60 秒；低速连接会退出重试。超时终止整个 Git 进程组（Windows 使用进程树清理）。

## AI 与凭据

子应用依赖统一消息接口。文本与图像生成分别配置超时：文本默认 180 秒，图像默认 600 秒；旧设备配置缺少图像字段时使用默认值，取消机制保持一致。默认 Codex 在后台自动发现、检查登录并保存设备配置；执行文本任务时使用隔离临时目录、只读限制，取消/超时应终止任务。文本助手只有用户勾选时才附带当前内容。API Key 和 GitHub Token 属于设备配置，不随源码或用户内容共享。

数据文件受到本地文件权限保护，不应宣称已通过系统 Keychain 加密。图像和远程 API 的支持范围见实际适配器与 AI 文档。

## AI 编辑器写入边界

- 容器内补原型是独立 `layout` 能力，不再把空矩形理解成“没有文字无法修改”。选中未旋转矩形/Frame 后纳入其内部已有元素，只向模型提供该区域的局部坐标、保留区域与样式。新控件通过 Excalidraw 转换并在实际尺寸上验证边界、Frame 归属及已有内容碰撞，禁止越框或覆盖原文。
- `layout` 新元素继承容器描边/线宽/线型；显式手绘要求使用手绘字体与粗糙度，绝不改原有样式。每步记录撤销并重查编辑冲突，后续对话包含新控件。容器框内布局与独立 diagram/既有 changes 分开执行；收到框内要求不能回退成仅文字建议或在右侧另画一份。
- 白板 AI 采用统一对话和受限操作计划，不以选区、页签或应用按钮作为必须步骤；发送授权对当前文件生成或修改。可选附加选区用于收紧范围。自动读取白板内容的勾选状态与发送范围必须明确显示，图片/私有元数据不发送。
- 模型规划和画布执行是两个不同阶段。当前文本接口返回完整 JSON 计划后，客户端按真实场景更新逐步执行、报告完成步数；不得伪称为模型 token 级工具流或模拟鼠标操作。每步保证绑定有效，记录撤销，不整体替换已有画布。
- 分步执行每次读取最新场景，比较受影响旧元素与本次生成元素，遇到并发修改、撤销、切换画布、同步激活或停止信号时中断后续步骤。保留并保存已完成部分，报告部分完成；不为视觉效果回滚用户编辑。取消/退出生命周期同时管理推理和本地执行任务。

- 文档/白板助手以编辑区右侧的布局内侧栏展示，不使用弹窗覆盖编辑器；切换文件重建对应会话，关闭侧栏取消尚未应用的生成。
- 白板可选的“加入对话”固定用户选区的快照，自动包含绑定文字；选择容器时纳入其内部内容，但不扩展到外部相邻节点。发送修改要求即授权对该快照直接应用；不再要求第二次“应用”。与文档生成草稿的预览确认流程分开。
- 选区协议只允许现有 ID 的文字、受限位置/尺寸变化。样式、元素 ID、组、绑定、文件和选区外元素由客户端保留。先校验源选区未改变，合并进当前全场景，再通过 Excalidraw `updateScene` 记录可撤销更新；不重挂整板、不清空历史、不覆盖生成期间的选区外编辑。
- 取消、切换画布、选区过期、同步激活或文字输入尚未结束时拒绝新写入；保存失败不得再次发送造成重复。受限范围（图片、嵌入、删除、改写旧连接关系、连接节点布局等）应提示不支持，不能用模型原始 JSON 覆盖整板。

文档改写采用“受限结构化草稿 → 校验 → 预览 → 用户确认 → 工具适配器”流程；白板生成使用同一受限图形协议，由对话授权后自动分步执行，模型仅生成内容，不直接调用文件系统或执行 UI 命令。文档纯文本块转换为安全 HTML；白板节点、连线和框内控件转换为真实 Excalidraw 元素，ID 由客户端重新生成，禁止模型提供脚本、图片 URL、路径或任意嵌入。

草稿绑定来源文件及内容快照，替换时校验未变，追加基于最新内容，跨文件禁止误写。写入前先保存原内容；调用模型期间不持工作区锁，只有应用阶段阻止同步激活。写入后更新编辑器版本以立即显示，旧版本回调不能回填覆盖；保存失败区分“未应用”和“已应用但未落盘”，防止重复追加。文档草稿附带内容保持显式勾选、默认不发送；白板对话显示默认开启的“读取当前白板”选项，用户可关闭，发送即授权使用该范围并执行计划。

详见 [AI 接入说明](ai-service.md)。诊断/模拟模型测试不能代替真实 provider 输出质量和原生 UI 验收。

## 三种仓库用途

1. `littleweb/workstore`：公开源码、团队上下文、GitHub Releases。
2. 每位用户自行配置的数据仓库：个人工作区同步，建议私有。
3. 应用 `.workstore/` 内的 Git checkout：可替换的本地传输缓存。

三者不能混用。跨设备开发通过标准 Git 分支和项目上下文文件；应用内同步不会自动提交代码或同步 AI 工具的私有聊天历史。


## HTML 原版接入阶段

用户要求先保持 HTML Anything 当前界面与功能，再做 WorkStore 改造。当前 `app.html` 嵌入固定上游 revision 的完整 Next 应用；`vendor/html-anything/` 原始文件有逐文件哈希回归，未改写 UI、模板示例、Agent 选择、提示词、流式生成、动态预览、导入、历史、市场、发布与导出实现。此前静态工具留在 `LegacyHtmlApp.tsx` 作迁移参考，独立作品文件保留，不再作为当前入口。

这是一项明确的分阶段例外：本阶段保留上游 Agent/模型设置及 localStorage/IndexedDB 存储语义，不提前统一成 WorkStore AI 或数据同步。统一改造须在原版验收后进行；其他子工具继续使用容器统一 AI。原版作品不应被描述为已接入工作区 Git 同步。

桌面包内置当前平台 Node 和 Next standalone 产物，由 `html_runtime.rs` 启动，只监听本机回环地址，不要求用户另装 Node 或维护服务。代码运行副本位于应用缓存，端口存入设备配置，避免变换 origin 导致原版浏览器作品看似消失。端口冲突报错，不静默换端口；已有文件不清除。生成进程随停止/退出清理，页面切换时保持已打开的 HTML 实例，不中断上游后台任务。

构建时仅在临时副本增加不可见的宿主桥接：退出/更新前停止活动生成、读取原版任务和历史并原子写入设备私有备份；原版 blob 下载转到原生保存对话框，保留生成文件原字节。设备模型路径、发布配置及浏览器快照不写进源码或共享工作区。iframe 与 WorkStore 不同源，不授予 Tauri IPC；容器 CSP 只新增回环 frame 来源，不放宽主页面脚本策略。外层 sandbox 不允许导航主容器，但保留原版脚本、弹窗、剪贴板和下载所需能力。

来源、许可、构建步骤与可审阅的适配边界见 `third-party/html-anything/README.md`。构建不代表真实 Agent、远端发布或原生 WebView 的全部导出格式已实测。

打包依赖使用 `app.tar` 完整保留隐藏目录与相对符号链接，首次运行解包至按构建标识隔离的设备缓存。

按用户要求，HTML 默认 Agent 为 Codex；宿主通过 `CODEX_BIN` 传入已有 Codex 路径识别结果，避免 GUI 的精简 PATH 使原版检测失败。默认选择在原版状态加载后迁移一次，保留之后的人工改选。

## 笔记与创建入口（2026-09-24）

文档应用显示名改为笔记，保持 app.doc、文件格式、路径和命令名兼容。笔记及白板的创建入口以加号图标加文字的普通列表行展示（透明背景、无边框、左对齐），固定在各自导航标题下的“创建”区，列表在其下独立滚动，底部不再重复创建。主导航展开时设置按钮位于顶部更新按钮右侧，与折叠状态共用设置功能。

## 封面大师

`app.cover` 采用列表工具统一导航：顶部创建区、42px 标题栏、稳定最近顺序与独立折叠。创建流程为分类选模板、填写配置、进入编辑页生成；生成中的状态局限于封面区域，右侧设置保持可编辑。标题栏只在创建流程显示两步切换，不重复放置配置页标题。

`src/covers/` 管理模板目录、提示词适配、版本与导出，`covers.rs` 使用独立 `.cover.json` 文件、原字节备份及版本 token。图像引用统一 `data/ai-images/` 的内容寻址资产，PNG 导出保留原图，ZIP 备份包含作品 JSON 与引用图片。每次生成新增版本，不覆盖既有图片。网络期间允许保存和同步，结果必须匹配来源文件、配置快照和远端版本；过期结果不会覆盖新编辑。

handraw-style 作为有版本与哈希的公开设计资源打包，包含所有风格及参考图，运行无需本机安装技能。图像生成仍走统一 AI；只有实际已确认的图像模型身份可以使用校准表免参考图，不能由 Codex 推理模型名称推断。技能的画风图只约束视觉风格，编辑目标图独立标记。模板内容与生成作品分开，设备设置与用户内容不进入源码。
