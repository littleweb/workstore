# 第一批实现：本地桌面基础版

标题与描述已调整为同一行，描述在空间不足时省略并支持悬停查看。ToolHeader 保留可选居中 Tab 和右侧操作插槽。

## 数据可靠性

Rust 在受控工作目录内写入固定文件，不接受任意前端文件名。JSON schema、工具 ID 唯一性、输入长度和颜色格式均校验。写入使用同目录临时文件、sync_all、原子替换，Unix 下同步目录元数据。相同内容不重复写，也不覆盖上一版备份。

同一工作空间持有操作系统文件锁，进程退出后释放。每次保存比较上次已知文件字节；检测到外部修改则停止覆盖，并保留编辑器输入。此版本没有实时外部编辑合并器，冲突时需先复制保留当前输入，再重新打开工作空间。

UI 加载完成之前禁用保存，避免默认值抢先覆盖磁盘数据。保存防抖 300ms，任务串行。关闭窗口与菜单退出先执行保存；失败时显示信息并保持窗口。突然断电/强制终止仍可能丢失尚未触发保存的最近输入，文件替换不会出现写一半的 JSON。

## 目录迁移

只接受现有空目录；拒绝与原目录互相包含。拒绝工作目录中的符号链接。新目录锁定后复制文件，逐文件字节校验，成功后原子更新 bootstrap.json 并切换运行时目录。源文件不删除。

复制失败时源目录和指针保留，目标可能留有此次复制的部分文件，重试请选另一个空目录。此阶段不自动合并两个已有工作空间，也不迁移历史备份和锁文件。目录监听、巨量附件迁移进度和取消留待后续。

## 平台与权限

macOS 覆盖标题栏与原生交通灯；Windows/Linux 保留系统标题栏。React 工具不直接获得文件系统插件权限，使用限定命令调用 Rust。仅本地主窗口允许调用命令；外链只允许系统浏览器打开 GitHub。剪贴板只申请写入文本，不读取系统剪贴板。单实例插件避免重复启动多个主窗口。

## 2026-09-15：本地优先的多设备同步

已将 Git 网络操作移到后台线程和 `.workstore/sync-repository-<仓库标识>/` 私有目录。用户工作目录不再执行 pull/rebase/reset；每次同步执行 fetch、基于本机上次同步基线的三方合并，以及普通 push。其他设备抢先推送时重新拉取、合并，最多尝试三轮，不强制推送。

触发时机：桌面工作区加载且启用同步后、窗口重新获得焦点、页面重新可见、恢复联网、每隔 60–70 秒，以及本地保存后 3 秒。检查即使没有本地修改也会拉取。失败采用 5 秒到 5 分钟的退避，后续触发自动重试。应用退出后不运行独立守护服务，下次启动补齐变更。系统仍须安装 Git；不依赖 WorkStore 服务端。

工作区文件（包括导航、常用、最近、排序、小工具输入、文档和白板）参与同步；`.workstore`、`.git`、`.DS_Store` 和旧版派生 `sync-metadata.json` 不作为用户数据同步。配置目录中的设备路径、窗口启动偏好和 GitHub 凭证留在各设备。本机同步基线记录在 `.workstore/sync-base.json`，不会上传。列表元信息以原始文档字段为准，不再每次生成时间戳造成空提交。

新设备首先检查远端，下载后校验工作区版本与文档类型；全新默认状态采用远端状态，已有本地文件参与合并。网络、认证、分支和数据校验失败均不会清空本地文件。建议使用专用空仓库，或已有 WorkStore 数据的仓库。切换到另一个仓库或分支需使用独立工作目录，避免误用原基线。

合并采用共同基线：单边修改直接采用，独立 JSON 字段自动合并，导航按工具 ID 合并。文档正文或白板元素等不能安全合并的内容保留冲突副本，文档/白板副本使用稳定 UUID 并出现在列表；其他文件冲突保存在 `conflicts/`。删除根据共同基线传播，修改与删除冲突也保留内容。最近访问时间、更新时间等取较大值，但不以设备时钟决定正文取舍。

网络期间可以继续编辑。推送成功后先刷新本地保存，再短暂阻止新输入、在存储锁内应用远端变更；网络期间已改动的文件保持原样并留待下一轮合并。文件激活前写入恢复日志，重启时完成文件与基线的提交。激活后同步刷新工作区状态、文档/白板缓存及编辑器；只有正文/画布变化才重建编辑器，减少不必要的初始化与同步回写。

验证使用临时本地 Git 仓库模拟多设备，不触碰用户 GitHub 数据。覆盖首次上传、新设备拉取、无本地修改时拉取、独立字段合并、删除传播、网络期间继续编辑、冲突副本、失败保留文件、崩溃恢复和空闲不产生提交。跨系统实际运行和真实 GitHub 网络认证仍需设备环境验证。
