# WorkStore 全局 AI 能力

## 使用

设置 → AI 默认选择本地 Codex。设备需安装支持 `exec --ignore-user-config` 的 Codex 并执行 `codex login`。可自动查找安装位置，也可指定可执行文件的绝对路径；每次启动都会在后台自动查找 Codex、检查登录并保存检测结果，不阻塞窗口、不弹窗，也不产生模型请求。已有 API 服务选择、模型和密钥保持不变。本地 Codex 是调用入口，推理仍需连接其模型服务。

网络代理留空时，macOS 自动使用系统 HTTPS 代理（环境变量优先）；其他系统使用代理环境变量。也可显式设置 HTTP/HTTPS 代理 URL，或输入 `direct` 直连。自动配置脚本 PAC 尚未支持。本机模型 API 始终直连。

可切换为 OpenAI 兼容 API：填写 base URL（例如 `https://api.openai.com/v1`）、模型名称和 API Key。地址不要带 `/chat/completions`，适配器会追加。HTTPS 是默认要求；本机 HTTP 服务也可使用。只支持文本 Chat Completions，不包含图像输入、工具调用和流式显示。

AI 对话、文档和白板均可使用。工具助手默认只发送输入问题；勾选“附带当前内容”才发送当前文档纯文本或白板文字元素。不会自动上传图片、附件或整个工作目录。对话历史中附带过的上下文仍属于该对话，开始新对话可清空。

## 子应用接口

```ts
import { ai } from '../ai/client';
const controller = new AbortController();
const response = await ai.generate({
  toolId: 'app.example',
  messages: [
    { role: 'system', content: '请帮助用户整理想法。' },
    { role: 'user', content: '用户明确提交的内容' },
  ],
  record: true,
}, controller.signal);
// response.text；response.saveError 非空时回答已生成，但保存失败，应提示复制保存。
// controller.abort() 可停止调用。
```

工具也可复用 `AiAssistantButton`，并通过惰性的 `context()` 提供当前选中内容。纯功能调用可省略 `record`，由工具自行保存结果。生成结果不自动覆盖用户文稿。

## 存储和同步

- AI 配置位于应用配置目录 `ai-settings.json`，包含设备路径、provider、model、timeout 和 API Key。Unix 上权限为 0600；Key 不返回前端，不进入工作目录和 GitHub 同步。这是本机受文件权限保护的存储，不是 Keychain 加密。
- 开启记录的每次完整回答保存为工作目录 `data/app.ai/<UUID>.ai.json`。记录包含最后问题（以及明确附带的上下文）、回答、工具标识、服务名称和时间；它是独立回答记录，并非完整会话文件。
- UUID 文件不会因不同设备同时使用而互相覆盖。沿用现有后台同步和刷新机制；界面按工具显示最近 30 条，其余文件仍保留。
- 首次接入的新设备可以拉取已有回答，但需要自己的 Codex 登录或 API Key。

## 后台和扩展

React → 统一 client → Tauri 命令 → Rust provider 路由。Codex 通过参数数组和标准输入调用，在空临时目录、只读沙箱下运行，禁用 shell、补丁与搜索工具，并忽略用户 agent/MCP 配置。没有 shell 字符串插值。兼容 API 使用 Rust HTTPS 请求，禁止重定向携带密钥。

每个请求最多 128 KB 消息、最多 80 条消息；最多同时 2 个请求。默认超时 180 秒，可配置 10–600 秒。取消和超时会终止本次 Codex 子进程或释放 HTTP 请求。调用期间不持有工作空间锁；退出、更新或迁移工作目录前，统一生命周期会停止并等待未完成请求。

新协议可在 Rust `generate` 路由下添加适配器，继续返回统一文本结果，子应用不依赖供应商 SDK。当前兼容接口已用本机模拟服务器验证协议，实际第三方服务需使用用户提供的 Key 验证。

参考：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 图像生成（小漫画）

沿用 `ai.generate`、全局设置、登录、代理、并发和取消机制，传入 `image: true` 与可选 `references: string[]`（最多 8 张 PNG data URL，每张最多 6 MB）。默认 Codex 调用内置图像工具，响应新增 `images` 数组，值为 `workstore-image:<sha256>`。文本请求保持原行为；OpenAI-compatible 文本适配器不假定支持图像接口。

CLI 当前不会把图片作为专用 JSON 事件输出。网关只接受 `thread.started` 的 UUID，在该任务自己的 `generated_images/<UUID>` 目录读取普通 PNG 文件，不读取回答里任意路径。图片存入工作区 `data/ai-images/<sha256>.png`，通过 `ai_read_image` 读取，随工作区同步。历史版本仅保留图片 ID，不重复复制图像。取消/超时由现有 kill-on-drop 机制终止 CLI；已经完成并保存的漫画页不会丢失。

真实服务验证（会调用本机默认登录）：
`cargo test --manifest-path src-tauri/Cargo.toml local_codex_image_smoke -- --ignored --nocapture`

## 文档 / 白板编辑联动（2026-09-20）

### 框内补充手绘原型（2026-09-20 修正）

用户反馈“在选区里面参照手绘风格完善创建作品原型”只得到建议，原因是旧协议只允许修改既有文字，新增图形又固定放到右侧。当前增加独立 `layout` 能力：即使加入对话的区域只有空矩形，也可在内部生成标题、说明、表单框、按钮、分隔线等真实可编辑 Excalidraw 元素。

操作：选中目标矩形或 Frame → 加入 AI 对话 → 输入“在这里参照手绘风格完善创建作品的产品交互原型” → 发送。面板会标明“框内绘制区域”。无需再选生成模式，不需要用户手动把生成图移回框内。

- 容器识别限于未旋转、未锁定且可唯一识别的矩形/Frame。附加容器时纳入其内部元素作为保留区域与上下文，包括不能直接修改的锁定/图片子元素；左侧导航、外部 Frame 和其他范围不发送。不能仅因为只选中了外框就认为内部一定空白。
- 通过 `regionLayout.ts` 提供边距内的局部设计坐标（宽1000，高度按容器比例），模型返回 `layout.containerId`、`style` 和最多60个 `items`。items 只允许 text、rectangle、ellipse、line，支持纯文本和受限字号，不接受原始 HTML、脚本、文件路径、链接或任意属性。
- `style=inherit` 继承容器的描边/线宽/线型/粗糙度；用户要求手绘时 `hand-drawn` 保留描边风格并使用手绘字体及至少1的粗糙度，仅作用于新增元素，不改原容器和其他元素。绑定文字与图形保持相同 Frame 归属。
- 在真正转换为 Excalidraw 元素之后再检查边界，文字自动扩容导致越界也拒绝；不是只检查模型建议的外框。生成前和每一步均检测与已有内容重叠；用户绘制的新控件也受到保护。遇到冲突/取消保留已完成部分，继续支持逐步撤销。
- Frame 内生成的控件设置正确 frameId 并保持层次顺序；矩形内控件放在原框之上，原矩形和左侧导航不变。后续对话范围会包含新增内容，避免继续按空框重复生成。
- `layout` 不能与独立 diagram 或既有元素 changes 混合执行。选中可绘制容器时禁止用 diagram 绕到框外；已有内容需要先改后补时可连续对话分次完成。不能安全容纳的布局明确报错，不清空容器或覆盖原有内容。

这里生成的是白板中的产品交互原型图，不会把手绘“生成作品”按钮变成可运行的业务代码。当前仍未调用真实模型验收输出质量；测试使用与截图相似的外框+左侧导航+内部区域和实际 Excalidraw 转换、绑定与保存数据。

### 当前交互：常规对话驱动白板（2026-09-20 更新）

白板右侧现在只有一套常规对话，不再区分“选区对话 / 生成新内容”，也不需要预览草稿后点应用。用户输入诉求、发送，助手自行返回回答、生成新图、修改现有文字/独立图形布局，或组合执行。空工作区生成时自动创建白板；可连续追问。

- 默认勾选“读取当前白板的文字与图形信息”，发送按钮旁说明数据范围；取消勾选后不发送当前场景，仍可独立生成。框选“加入 AI 对话”成为可选的范围限定，可移除，不是发送前置条件。仅发送可编辑元素的文字/几何/样式，不发送图片文件、customData、路径或选区外参考。
- 模型返回受限 `whiteboard-turn` 操作计划：`message`、已有元素 `changes`、独立新图 `diagram` 或框内新增 `layout`；先整体解析、校验范围与支持类型，再执行。纯问答没有操作时只展示回答，不强行绘图；不执行模型代码或任意原始 JSON。
- 对话区明确区分“理解需求/规划”与“绘制/连接/修改”。当前网关并非 token 级工具流：完整计划到达后才按约 220ms 的步骤间隔将真实图形/文字/连线写进 Excalidraw，每一步驱动画布和进度提示。不是预览动画或模拟鼠标；不伪称模型仍在推理时已经修改。
- 生成按节点及其标签成组落入画布，随后连接箭头；中间状态也保持有效的正反向绑定。未限定容器的独立新图放在当前最新内容右侧；选中矩形/Frame 时通过 layout 放在内部留白。两种路径都保留原有内容，不额外发送范围外资料。
- 每一步使用 `updateScene` 的即时历史记录，可逐步撤销；执行中可以停止或关闭侧栏，停止后保存已完成部分，不回滚覆盖用户后续编辑，不把部分完成报告为全部成功。应用期间更改 AI 正在操作的元素/撤销或切换文件，会停止后续执行；不相关旧元素的编辑被保留。
- 退出、安装更新和迁移工作区时，`stopAiRequests` 同时取消并等待模型调用及后续本地画布执行，防止退出后仍有绘制任务写文件。保存失败显示真实结果并提供“重试保存已执行内容”，不自动重跑计划。
- 支持边界仍是生成节点/连线、现有文字及不连接箭头的独立形状几何调整；删除、图片、任意连线重排、锁定元素仍拒绝。模型应说明限制，而不是用“已完成”假装执行。

主要代码：`src/whiteboard/SelectionAssistant.tsx`（统一对话），`conversationPlan.ts`（上下文与计划协议），`conversationTarget.ts`（真实分步画布执行）。文档侧栏维持生成/改写与预览确认流程；本次实时操作调整针对白板。

### 选区能力与原有编辑保护

文档与白板点击“AI 助手”后，在编辑区右侧显示布局内的侧栏，不再打开 AI 弹窗或遮罩；打开/关闭面板不会卸载当前编辑器。文档保留生成/改写与对话两页，原来的文档草稿预览/追加/替换规则保持不变。

限定白板修改范围时，可选地使用以下选区流程：

1. 使用 Excalidraw 选择工具，拖动框选或点选要修改的元素。
2. 点击白板顶部“加入 AI 对话”，或右侧“将选区加入对话”。与图形绑定的文字自动包含在选区内，不因为连线而扩展到其他节点。
3. 右侧显示选区缩略示意和元素数量。之后再次框选不会悄悄替换已加入的范围；需显式重新加入。
4. 输入修改要求并点“发送并更新选区”。这一步明确授权按请求自动写入此选区；模型返回、校验通过后直接修改并保存，不再二次点应用。后续对话使用已更新的选区快照。
5. 使用白板原有撤销操作回退这次更新。写入使用 `updateScene` 加 `CaptureUpdateAction.IMMEDIATELY`，不清除原撤销记录。空白图的第一步会定位新增内容；其他情况不强制改变用户视口或选择。

**样式和数据边界：** 输入只发送已加入选区的文字、位置、尺寸与样式，不发送整板、图片文件、路径或 customData。模型只能返回选区现有 ID 的受限文字/位置/尺寸变更，不能提供字体、颜色、线型、分组、链接、图片或删除指令；这些字段由客户端保留。未选中元素使用当前最新对象，不受替换影响。生成后选区若已编辑/删除、切换了白板或更换了画布会话，拒绝写入；生成期间只改了选区外内容时可继续应用。关闭侧栏、换页、重新加入选区或停止生成会取消旧请求；迟到结果不写入。

当前可修改既有文字/标签以及未连接箭头的独立矩形、椭圆、菱形的位置/尺寸；已连接节点可改文字，但会改变其连接几何的布局/自动扩容会被拒绝。图片、嵌入、锁定元素不能直接修改；画框可以作为框内新增容器；重写选区内部拓扑、删除元素、连线重排与任意复杂场景重建尚未支持，失败时明确提示并保持原内容。新建图形通过同一个对话请求生成：选中容器时使用 layout 在内部补充，没有容器时使用 diagram 放到旁边。

写入前保存原场景；同步正在激活或仍在编辑文字时不写入。分步执行中的每一步都是同步比较与替换，落盘失败会明确显示“已更新但未保存”，暂时禁用继续发送，可用对话中的“重试保存已执行内容”恢复，避免重复执行。

主要新增代码：`src/ai/AiSidebar.tsx`、`src/whiteboard/SelectionAssistant.tsx`、`selectionEditing.ts`、`selectionTarget.ts`。测试覆盖右侧布局、加入范围、样式/ID/连线保留、选区外变化、过期拒绝、取消、直接应用与保存失败；真实模型输出质量和原生视觉效果仍需实际验收。

### 生成新内容的草稿流程

文档侧栏提供“生成 / 改写”与“对话”；下述草稿预览确认主要用于文档。白板已改为上述统一对话自动执行，原结构化节点协议作为操作计划的 diagram 使用，不再显示生成页签。输入要求 → 生成草稿 → 预览 → 选择追加、替换或另存为新文件 → 确认应用。草稿标题仅用于新文件，追加/替换不悄悄重命名当前文件。没有文件时也可用 AI 新建。

- 文档协议：受限 JSON 块（标题、段落、无序/有序列表、表格）。字段校验后将纯文本转义成 HTML，再写入 TeaEditor；模型不能提交脚本、事件属性、远端资源或直接执行编辑器命令。
- 白板协议：受限节点和边，包括矩形、椭圆、菱形、节点文字及连线标签。校验 ID、引用、数量和坐标后，通过已安装 Excalidraw 的 `convertToExcalidrawElements` 转成真实可编辑元素，生成全新 ID。追加保留现有图形/文件并放到右侧，重新载入时定位内容；不是把自然语言回答当成白板图片。
- 调用仍经过统一 `ai.generate`，沿用全局 provider、取消和超时。明确要求模型返回实际内容，只有“已插入/待处理”等文字或非法 JSON 时拒绝应用，不宣称文件已变更。
- 文档草稿的“附带当前内容”默认不勾选。勾选后才把来源资料发送给所选模型；最长 50,000 字符，白板只提取元素结构/文字，不发送文件图片数据。参考资料作为不可信数据处理。AI 历史会保存请求和生成结果，属于用户工作区数据。
- 每个草稿绑定生成时的文件 ID、标题和内容快照。替换前若内容或标题变化则拒绝覆盖；追加基于当前最新内容；文件已切换时不得写入新选文件，可另存为新文件。旧编辑器回调使用版本标记避免回写覆盖已应用草稿。
- 应用先保存当前内容，失败则不写入；应用后使用工具现有保存队列和 token 校验落盘，并触发自动同步。应用阶段注册同步激活保护并防止重复点击，侧栏不能在应用中关闭。若新内容已进入编辑器但磁盘保存失败，明确提示且草稿不可重复追加，由原有保存重试处理。

主要代码：`src/ai/editing.ts`（协议、校验、请求与内容转换）、`src/ai/EditorAssistant.tsx`（预览与确认）、`src/documents/aiTarget.ts` / `src/whiteboard/aiTarget.ts`（编辑器适配）。`tests/ai-whiteboard.test.mjs` 使用真实 Excalidraw 转换和恢复代码，canvas 测量为 DOM 测试适配；模型调用使用测试响应，不冒充真实模型验收。

示例：

- 文档：勾选附带内容，输入“整理成项目方案，补充实施步骤和验收清单”，生成后选择替换正文；未附带时可输入“写一份包含目标、进度、风险的周报模板”后追加/新建。
- 白板：在常规对话输入“绘制需求评审、开发、测试、发布流程，测试失败返回开发”，发送后规划并直接分步绘制；然后继续输入“把英文改成中文”，无需切换功能页。

支持的是结构化正文和节点连线草稿；不是任意编辑器命令执行，也不承诺无损修改复杂既有白板的每个原始元素。复杂图形优先追加或另存，替换需用户确认。
