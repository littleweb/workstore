# WorkStore 自动更新

客户端使用 Tauri 官方 updater。折叠按钮左侧为检查更新按钮；启动 10 秒后、之后每 6 小时检查。发现更新显示绿点，点击下载，展示进度。下载完成后暂停数据同步、保存所有文档，再安装和重新启动。保存失败时不安装，响应读取中断、连接错误或超时会最多尝试下载 3 次，每次重新下载并由插件验证签名；签名校验失败不自动重试。下载或签名校验失败时保留现有版本。更新包与工作区目录分离，不覆盖用户数据。

更新来源是发布者的 GitHub Releases，与每位用户的数据同步仓库无关。当前接入的是静态 latest.json，因此发布仓库须允许匿名下载安装包。私有源码可以保留在另一个仓库；不要将发行者的私有 Token 打包进应用。

## 一次性配置

本机已生成更新签名密钥，私钥位于 `~/.tauri/workstore-updater.key`，公钥位于同路径的 `.pub` 文件；公钥已经写入 Tauri 配置。私钥权限为仅当前用户可读写，须另行安全备份，不得上传到源码或 Release。这个签名与 Apple Developer ID / 公证是两套机制；macOS 对外发布仍应完成 Apple 签名和公证。

确定公开的安装包仓库后执行：

```sh
node scripts/configure-updater.mjs littleweb/workstore ~/.tauri/workstore-updater.key.pub
```

首次部署需要安装一次含更新入口、正确发布地址及公钥的新客户端；此前没有更新功能的旧版不能自行升级到这个引导版本。

## 发布后续版本

1. 同步增加 `package.json`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json` 的版本号，版本必须高于用户已安装的版本。
2. 在对应平台构建并签名：

```sh
export TAURI_SIGNING_PRIVATE_KEY="$HOME/.tauri/workstore-updater.key"
npm run desktop:update:build
```

如私钥设置了密码，再设置 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。Windows PowerShell 使用 `$env:TAURI_SIGNING_PRIVATE_KEY`。不能更换已交付客户端信任的签名密钥。

3. 收集各平台的更新包及相邻 `.sig` 文件。macOS 使用 `.app.tar.gz`，Windows 使用 `.exe` / `.msi`，Linux 使用 `.AppImage`；DMG 供首次安装使用，不能作为自动更新包。
4. 生成发布清单，例如 Apple Silicon Mac：

```sh
node scripts/create-update-manifest.mjs littleweb/workstore darwin-aarch64 src-tauri/target/release/bundle/macos/WorkStore.app.tar.gz
```

可在同一次命令后追加其他平台与文件的配对参数。脚本在 `release-assets/` 生成带平台前缀的文件，避免 Intel 与 Apple Silicon 同名覆盖。`latest.json` 必须同时包含此次支持的全部平台。

5. 在安装包仓库新建与版本匹配的 `v版本号` Release 草稿，上传 `release-assets/` 中本次生成的更新包、签名和 `latest.json`。确认附件完整后发布为 Latest 正式版本。预发布版本不会进入当前稳定更新通道。

客户端从 `https://github.com/发布者/仓库/releases/latest/download/latest.json` 获取版本信息。清单中的每个平台使用固定版本的下载地址与对应签名，防止下载过程中 Latest 改变造成包与签名错配。

## 验证范围

自动化测试覆盖：检查与安装分离、下载后先保存再安装、保存失败禁止安装、下载/校验失败不安装、失败后重试和状态恢复。必须再使用两个正式签名版本，在可写的应用安装目录中验证真实在线升级。macOS、Windows、Linux 应分别验收；本机 macOS 构建不能替代其他系统实机验证。
