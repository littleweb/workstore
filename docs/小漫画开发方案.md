## 1. 可行性与现状

可行。采用“客户端内置解释能力 + 远程纯数据模板 + 本地作品快照”。在既有协议和能力范围内，追加题材、故事结构、画风、参考资产和完整预览无需软件发版。新增渲染类型、模型适配器或不兼容协议仍需升级客户端。

核查结果：

- 本地为 React 19、TypeScript、Ant Design 6、Tauri 2 工程，已有白板文档缓存、保存前刷新及 Rust 本地持久化，可复用模式；尚未安装 React Flow。
- 已有软件更新服务 `src/updateService.ts` 和工作区 Git 同步 `src-tauri/src/sync.rs`。模板拉取应独立为只读内容服务，不调用软件安装更新，也不把公共模板源配置成个人工作区同步仓库。
- 2026-09-15 GitHub API 确认 `littleweb/workstore` 为公开仓库，默认分支 `main`；当次根目录检查仅见 README.md，模板目录尚未建立。网页浏览曾返回 404，随后匿名 API 访问成功，以当次 API 实查为准。
- 本地工作目录未识别为 Git checkout；本轮只在本地记录方案，不宣称已经提交或同步到公共仓库。

## 2. 已确定的页面与交互

- 左侧依次为创建作品、爆款作品、我的作品列表，沿用列表应用折叠行为。
- 创建页：模板列表、完整示例预览、简单主题输入；使用模板后进入作品编辑。
- 顶部标题栏左侧为作品名，中间为“漫画编辑 / 作品设定 / 历史版本”Tab。
- 漫画编辑：卡片单行横向排列，不换行，支持横向延伸与平移、缩放。点击卡片才出现右侧配置栏；关闭或点击画布空白处收起，并保留画布位置和未保存内容。
- React Flow 为候选画布方案：采用自定义卡片节点、固定同一纵坐标、关闭连线入口；初版不开放任意拖乱页面。滚动优先浏览，缩放使用快捷键/捏合或显式控件，避免误缩放。实现阶段再验证触控板、卡片文本编辑和侧栏展开的交互。
- 作品设定：主题、结构、画风、角色参考、场景和道具；改设定与重绘作品是两个动作，明确显示受影响页面。
- 历史版本：版本列表、只读横向预览、差异摘要、恢复。恢复创建新修订，原修订不删除。

## 3. 数据分层

| 层 | 责任 | 更新原则 |
| --- | --- | --- |
| CatalogIndex | 模板发现、分类、搜索、版本指针 | 小文件，可缓存；不含整套大图 |
| TemplatePackage | 通用创作规则、完整示例、参考资产 | templateId 稳定，每个 revision 不可变 |
| ComicDocument | 用户实际主题、角色、剧情、页面及资产 | 本地优先，不随模板更新自动改变 |
| WorkRevision | 作品历史快照与变更摘要 | 与模板 revision 分离，恢复产生新版本 |
| ExtractionReport | 示例来源、逐页证据、不确定项、发布检查 | 制作阶段保留；私有来源不自动公开 |

模板不是单个提示词。它需同时服务“看完整示例”“主题替换”“设定编辑”“连续分镜生成”“单张再生成”。固定示例内容与可复用创作规则分开保存。

### 3.1 持续追加的目录

推荐远端布局（main 分支，未来建立）：

```text
content/comics/
  catalog.json
  catalogs/<catalogRevision>.json
  schemas/catalog-v1.schema.json
  schemas/template-v1.schema.json
  templates/<templateId>/<revision>/template.json
  assets/<sha256>.<ext>
  README.md
```

`catalog.json` 是活动索引；`catalogs/` 留存已发布目录快照。新模板增加新 ID；同模板修订追加新 revision，保留旧包。索引的 latestRevision 可更新，模板条目首次 addedAt 保持不变；不把“追加”理解为索引文件永远不可更新。撤下使用 withdrawn 状态，默认不再推荐；必要时可因来源授权等原因移除公开资产，不承诺公共内容永久可取。

下面是字段形状示例，`<...>` 为占位符，不是可发布数据：

```json
{
  "type": "workstore.comic.catalog",
  "schemaVersion": 1,
  "catalogRevision": 1,
  "publishedAt": "<ISO-8601 UTC>",
  "entries": [{
    "templateId": "daily-animal-reversal",
    "title": "动物职场反转",
    "summary": "用一个日常误会，讲一个轻松反转的故事",
    "tags": ["日常反转", "动物", "暖色手绘"],
    "addedAt": "<ISO-8601 UTC>",
    "status": "active",
    "latestRevision": 1,
    "revisions": [{
      "revision": 1,
      "schemaVersion": 1,
      "requiredCapabilities": ["comic.panels.v1", "comic.text-layer.v1"],
      "package": {
        "path": "content/comics/templates/daily-animal-reversal/1/template.json",
        "sha256": "<64 lowercase hex>",
        "bytes": 12000
      },
      "cover": {"path": "content/comics/assets/<hash>.webp", "sha256": "<hash>", "bytes": 50000},
      "previewPageCount": 4
    }]
  }]
}
```

索引保留历史 revision 的兼容元数据，使旧客户端可选择最新兼容修订；不能只保留一个可能已不兼容的 latest 指针。列表以 templateId 去重，默认按 addedAt 倒序；展示排序不依赖目录枚举。规模变大后再引入分片索引，首版不逐条调用 GitHub 目录 API。

### 3.2 通用模板包字段契约

未来以 JSON Schema 2020-12 形成实际校验文件；此处先定义字段语义。

| 字段 | 内容与约束 |
| --- | --- |
| type / schemaVersion | 固定类型 `workstore.comic.template`、协议主版本 |
| templateId / revision | 全局稳定 ID、正整数不可变修订；与索引相符 |
| metadata | title、summary、language、tags、作者、创建时间、修订说明 |
| compatibility | requiredCapabilities；确需时增加 minAppVersion，当前不虚构最低可用版本 |
| inputs | typed fields；首版 theme 必填，tone、主角偏好等可选，含默认值、字数限制、示例与 allowOverride |
| output | 默认页数及允许范围、比例、阅读顺序、每页格数范围、文字语言；范围均需由已支持能力约束 |
| narrative | premisePattern、角色职责、冲突、故事节拍 beats、结尾策略、节奏限制、可变与不变部分 |
| visualStyle | 线条、色板、光照、材质、构图、人物比例、字体/气泡、排版留白和避用项 |
| entities | 角色、场景、道具的稳定 ID；外观属性、关系、参考图、默认锁定项、可替换属性 |
| pageBlueprints | 分页与分格规则、镜头、对白槽位、动作与状态变化；使用规则变量，不直接复制示例故事 |
| continuity | 角色/场景/道具状态约束、跨页引用、修改传播规则、检查项 |
| generationRecipe | 声明式阶段、支持的操作枚举、输入引用、输出要求；不包含脚本或可执行代码 |
| exampleWorks | 一个或多个完整可阅读示例，页序、格序、对白、参考图与分析证据关联 |
| assets | assetId、仓库相对路径、SHA-256、bytes、mime、像素尺寸、用途、来源与授权引用 |
| provenance | 来源清单、证据引用、observed/inferred/unknown 标记、未解决事项、制作者与提取流程版本 |
| publication | 原作来源、署名、预览再分发与生成参考的分别授权状态、发布状态 |
| extensions | 仅允许带命名空间的可选扩展；未知必需能力必须拒绝，不能静默忽略 |

所有角色、场景、道具、页面、分格、气泡、资产均有稳定 ID，禁止用数组下标充当跨页身份。引用必须可解析；矩形坐标统一为所属页/分格内的 0–1 归一化坐标，并标明坐标参照。

分镜字段示意：

```json
{
  "pageId": "page-02",
  "order": 2,
  "beatId": "first-attempt",
  "panels": [{
    "panelId": "panel-02-01",
    "bounds": [0, 0, 1, 1],
    "sceneId": "office",
    "entityIds": ["protagonist", "glasses"],
    "shot": "medium",
    "actionPattern": "主角第一次尝试主题中的任务，表现出故作镇定",
    "stateBefore": {"protagonist.wearing": ["glasses"]},
    "stateAfter": {"protagonist.wearing": ["glasses"]},
    "textSlots": [{"id": "speech-02-01", "speakerId": "protagonist", "kind": "speech", "intent": "故作轻松", "maxCharacters": 24}],
    "referenceAssetIds": ["character-front", "office-reference"]
  }]
}
```

固定示例的实际对白存入 exampleWorks.pages.panels.texts，不混入 actionPattern。可变页数应有 beats 到页面的映射规则；未实现扩缩页能力的模板只能使用固定页数，不能只改 pageCount 数值。

完整参考提取覆盖：页序/格序、原始文字和说话人、人物外观与关系、场景空间、道具位置、姿势表情、镜头、色彩与线条、气泡与文字布局、事件因果、情绪节奏、跨页状态。不能观察到的设定明确标 unknown，不能宣称反推到了原始提示词或隐藏设定。

### 3.3 模板实例化与作品历史

ComicDocument 拟包含：id、标题、常用标记、时间、schemaVersion、templateOrigin、templateSnapshot、resolvedSettings、entities、pages、assetRefs、currentRevisionId。

- templateOrigin 保存 templateId、revision、包哈希、catalogRevision、sourceCommit；templateSnapshot 保存实际使用的模板内容。
- 用用户主题解析成实际故事和角色参考后，冻结为本作品设定。保留必要参考资产的本地副本，不能只保存会失效的远程链接。
- 页面保存独立画面资产和文字层；调整对白不重画整张。新图生成成功后才替换页面资产。
- WorkRevision 保存 revisionId、parentRevisionId、时间、触发操作、涉及 pageIds/entityIds、差异摘要及可恢复内容快照。首版可采用完整 JSON 快照加内容寻址图片；普通自动保存不必每次产生可见历史条目。
- 恢复旧版本以当前版本为 parent 创建新版本，同时保存 restoredFrom；不改写原历史。
- 远端模板升级不自动覆盖作品。用户主动采用新模板修订时，显示差异、影响页和可撤销的新作品修订。

## 4. GitHub 动态分发

### 4.1 发布

制作模板草稿 → 校验包与完整预览 → 发布检查 → 将包和资产提交到仓库 → 再更新活动索引。

发布可由维护者通过 PR 合并，或由后续明确授权的发布操作完成。并发模板追加由 CI 从模板目录重新生成索引，检测重复 ID/revision；不得通过覆盖旧索引丢失其他人的新增模板。此处不设置实际 Actions。

### 4.2 拉取与一致性

1. 客户端先显示内置或最近成功的本地目录，打开创建页后异步检查；建议冷启动和超过 6 小时的页面进入触发，另提供手动刷新，失败退避。
2. 用 GitHub API 解析 main 当前提交 SHA，然后按该 SHA 获取 catalog.json、模板包和资产；整次下载固定同一个提交，防止索引和文件版本错配。
3. 使用 ETag/条件请求（源端支持时），保留最近成功 SHA；不依赖短期 download_url。固定提交的 raw 内容路径可作为读取方式，源地址通过受控仓库配置生成。
4. 先下载轻量索引和可见卡片封面；打开预览再取全页预览图，使用模板时确保所需包及参考资产就绪，不预下载整个仓库。
5. 检查类型、schema、能力、引用、资源大小及哈希；下载到暂存区，完整通过后原子激活模板包。活动目录可标识未下载/下载中/可用状态。
6. 断网、限流、404、坏 JSON、缺图或哈希不匹配均保留上次可用版本。新模板失败不影响其他已缓存模板；首次离线使用内置种子模板，不能显示假空列表。
7. 不兼容新修订回退到已知兼容修订；没有兼容修订时标注需升级。撤下模板不继续推荐，已有作品读取其本地快照。

公开读取无需用户登录或写入凭据。发布端需要维护者权限，不能在客户端内置 GitHub 写令牌。公共目录服务与私人作品同步彻底分离，个人作品和私有参考不会因为拉取模板而被上传。

### 4.3 缓存、资源与边界

- 桌面以独立 Rust 内容服务负责限定源网络读取与缓存，缓存拟放 `.workstore/cache/comic-templates/`；该路径不参与用户数据同步。
- 已实例化作品需要的参考图与历史图片进入作品持久资产区，不能由缓存清理回收；仅无引用缓存按 LRU 清理。
- 浏览器开发预览用独立 IndexedDB 缓存，实际 CORS 和 WebView 网络行为需验证。
- 模板仅含 JSON 和允许的位图资源，拒绝路径穿越、可执行脚本、任意 shell/网络指令和超限文件；描述文字不能覆盖客户端工具权限。SHA-256 用于完整性，不等同于独立的发布者签名。
- 预览使用压缩图片，原始大素材不作为每个客户端的强制下载项。GitHub 适合初期静态模板分发，不作为无上限媒体存储；大规模再扩展资源源站，保持包协议与内容哈希稳定。

## 5. “小漫画模板制作”技能规划

计划技能显示名：小漫画模板制作；建议 ID：`comic-template-maker`。本轮只设计，不创建或安装 SKILL.md。

职责：从用户提供的完整示例作品提取可追溯参考信息，抽象为上述 TemplatePackage，生成可审核的模板草稿。不是生成最终用户漫画的技能，也不把一份模板单独做成一个技能。一个技能持续生产多个数据模板。

### 输入

有序图片、长图、PDF 或可访问作品链接；可附作者、来源、授权用途和希望保留/替换的特征。缺页、阅读顺序不明、链接不可取时先保留已知材料，列明缺口；不能把补写的剧情标成原作事实。

### 流程

1. 识别文件、排列页序/格序、记录来源及内容哈希；PDF/图片按其适用能力逐页查看，OCR 与视觉核对。
2. 提取逐页对白、镜头、动作、角色/场景/道具和状态，建立 evidenceId 到具体页/格/区域的引用。
3. 形成角色与场景参考、画风说明、故事节拍与连贯性表；识别矛盾和看不清的信息，标注观察/推断/未知。
4. 将姓名、具体事件等示例事实抽象为可替换变量；明确默认继承画风/叙事结构、可替换角色资产的范围。
5. 输出 metadata、完整 exampleWorks、pageBlueprints、连续性规则和资产清单。原图能引用的就忠实引用；新绘参考标注 generated，不能冒充来源原图。
6. 校验 schema、ID 引用、页数/格数、文本层、资源哈希、完整预览与发布用途；形成 extraction-report.md，区分缺失和推断。
7. 后续具备生成链路后，用一个不同主题进行试生成，检查结构可复用性和角色连续性，记录费用及结果；没有试生成时标注未验证，不能声称效果合格。
8. 默认交付本地模板草稿与索引追加候选。只有明确要求发布时才走仓库发布流程；私有输入不得自动公开。

### 产出与发布门槛

计划输出 `template.json`、内容寻址 assets、完整 preview、`extraction-report.md`、`catalog-entry.json` 草稿。制作报告中的本地绝对路径、私人链接、私密笔记不进入公共模板包。

模板制作完成与允许公开是不同状态：来源授权未知可以保留 private-draft；公开预览需对应的再分发许可，生成参考用途也单独记录。缺完整示例时标 incomplete-reference，不可作为“可预览完整作品”的正式模板发布。置信度记录不能替代人工可核查的证据。

## 6. 开发阶段与验收

1. 协议：落实 JSON Schema、示例包、版本规则和资产验证器；覆盖缺引用、不兼容能力、重复 ID、页序错误。
2. 内容服务：缓存、固定提交下载、条件请求、兼容回退、离线种子；在客户端版本不变的情况下向远端追加模板并验证自动出现。
3. 产品：创建页预览、模板实例化、三个 Tab、横向画布、按需侧栏和可恢复作品版本；模板更新后旧作品不变。
4. 制作技能：按当前技能创建规范编写 SKILL.md 与配套校验/打包工具，用多种示例输入验证信息提取与草稿产出。
5. 发布：仓库目录、PR 校验与活动索引生成，验证两人并发追加不丢项、错误包不发布、撤下不损坏本地作品。

必要验收：冷启动离线、损坏索引、下载中远端更新、资源哈希不符、缓存清理后已用作品仍完整、模板与作品版本独立、恢复版本可撤回、发布不夹带私有来源。生成质量需用多页真实输出评估，不以 JSON 校验通过代替角色一致性验收。

### 8.2 创建与画布细则

- 默认选中“猫咪打工记”，标题、标签、预览页数由模板数据驱动。取消模板后允许继续输入，但发送需选择六套之一；自由无模板创作后置。

- 尺寸选择提供 3:4、9:16、1:1、4:3，默认 3:4；这是导出比例，实际模型像素规格由通用能力适配。优先匹配原生比例，必要时补留白/重新排版，不强行拉伸或裁掉主体。
- 张数拟提供 4、6、8，默认跟随模板；不同张数使用经校验的节拍映射，不能机械重复/删除页面。封面另算，不占漫画张数。
- 更多设置首版只收纳语气和结尾偏好；模型、Key、供应商不出现在小漫画独立配置中。
- 创建后立即建立本地草稿并进入编辑页显示分阶段进度；防重复点击。页面可显示排队、生成中、完成、失败、取消，重试只针对失败步骤。
- 采用 React Flow 作为第一版拟定实现：自定义页面节点、等间距单行、禁止连线及任意纵向拖动；数据仍以 pages.order 为准，不把画布坐标当故事顺序。
- 滚动/触控板优先平移，缩放用捏合、快捷键或 +/-，提供适应视图。图片按视口附近加载；选中页不能因侧栏展开而跳出视野。
- 右栏关闭不清空输入；操作面板内部点击不触发画布取消选择；切换页时保存草稿。插页/删页/重排用明确菜单并重新检查剧情影响，不依赖自由拖乱节点。

## 10. AI：统一使用 WorkStore 默认通用能力

### 10.1 2026-09-16 本地代码核查

依据 `docs/ai-service.md`、`src/ai/client.ts` 和 `src-tauri/src/ai.rs`：

- 已有统一 `ai.generate({ toolId, messages, record? }, signal)`，只接收文本 messages，返回 response.text；默认本地 Codex，可由全局设置切换 OpenAI 兼容文本 API。
- 已有取消、超时、生命周期停止和最多 2 个并发请求；不应由小漫画绕过。
- 当前没有图像输入、图像生成/编辑或图像资产结果接口；Codex 适配提示也明确只提供文本。不能将本会话设计图使用的 imagegen 工具当成 WorkStore 已有生图能力。

因此：**统一使用默认 AI 是确定要求；在通用层补齐图像能力是首版完整漫画生成的前置依赖。** 不在小漫画里另接供应商 SDK、另存 Key 或硬编码模型；也不为了生图静默切换用户默认服务。

### 10.2 通用层拟议增量（尚未实现）

| 能力 | 接入方式 | 需要验证 |
| --- | --- | --- |
| 剧情、分镜、对白、发布文案 | 复用现有 ai.generate，toolId=`app.comic`；结果做业务 Schema 校验 | 文本模型能否稳定输出需要的字段；非法输出有限修复 |
| 能力发现 | 拟新增 ai.capabilities，说明 text / vision / imageGenerate / imageEdit、参考图与尺寸限制 | 能力来自已配置适配器及可验证支持，不根据服务名称猜测 |
| 参考图解析与视觉检查 | 拟扩展通用多模态请求，传明确选取的资产 | 默认服务是否支持图像输入，参考图数量与大小限制 |
| 角色、场景、漫画页及封面生成 | 拟新增通用图像任务接口，返回受控本地资产 ID、格式、尺寸、任务状态 | 默认服务是否实际支持生成和参考图引导 |
| 单张调整 | 优先通用 imageEdit；缺少编辑但支持参考图生成时明确按参考重绘 | 重绘与局部编辑不是同一效果，不能假称像素级局部修改 |

具体接口命名待通用 AI 模块实现时确定。参考图只发送该作品所需资产；响应图片必须落入受控资产存储并校验，不能只记录临时远程 URL。调用路由、日志、密钥、代理、并发、取消和退出处理统一管理。

如果默认服务缺图像能力，允许模板浏览、设定与文字草稿，清楚显示能力未就绪并引导“设置 → AI”；完整生图为首版验收门槛，不能把仅有文本的降级模式当作已交付。通用层适配验证不得修改现有文本助手行为；此阶段不预承诺任何具体模型支持生图。

### 10.3 漫画生成流水线

1. 校验主题、模板、输出规格和 AI 能力，保存 jobId 与输入快照。
2. 文本生成结构化故事与全页分镜；校验页数、角色 ID、因果和对白长度。
3. 生成/复用角色及场景标准参考，固定画风与资产身份。
4. 分页生成图像：提供本页剧情、实体参考、状态及必要前页信息；依赖页顺序执行，独立任务也必须遵守全局并发限制。
5. 合成独立文字/气泡层，校验溢出；进行可执行的一致性检查，有视觉能力时增加视觉检查，失败项允许单页重试。
6. 资产与页面记录成功落盘后再激活，创建作品版本；对失败页保留旧图/占位及重试入口。

单页重生成默认锁住剧情、角色、场景和对白。改变角色服装/道具状态/事件时，计算关联页，展示“本张”或“同步相关页”的明确范围。新增任务绑定基础作品 revision；若期间用户修改同页，旧任务结果存候选版本而非覆盖最新编辑。网络断开或退出后保存进度；重新打开由用户选择继续，避免未经确认重复调用收费任务。

## 11. 发布物料与数据补充

第一版提供小红书、抖音、视频号物料配置；只准备图片和文案，不含自动对外发帖、平台账号管理和定时发布。平台尺寸/文字限制在实施时按当前官方能力核验，不把设计图示意数字硬编码为平台规则。

每个平台独立维护 PublishingDraft：id、platform、sourceWorkRevisionId、coverCandidates、selectedCoverId、coverTextLayers、titleCandidates、title、description、hashtags、orderedImageRefs、updatedAt、generationMetadata。生成元信息记录请求 ID 和输入版本，不包含密钥。

- 一键生成基于当前完整作品，产出候选封面、标题、描述和标签；单项可重生成，手动编辑即时保存。
- 一句话调整带字段范围和锁定项，例如保留封面只改文案；不同平台内容互不覆盖。
- 封面图与封面标题分层，修改文字不必再次生图；首轮候选可按请求生成，未生成的候选不填假图。
- 作品更新后标记物料可能过期，提示同步，不能静默覆盖用户写好的发布文案。
- 导出包含封面与排序后的漫画图片、标题/描述/标签文本及物料清单；支持复制文案。缺图时显示缺口，不能导出后宣称完整。
- 发布草稿属于作品本地数据及可恢复状态；恢复作品后保留草稿并标记其来源版本差异。模板远端更新不影响现有物料。

数据模型补充 GenerationJob：jobId、workId、baseRevisionId、operation、targetIds、stage、status、inputHash、completedAssetRefs、error、timestamps。任务运行态与重试日志不作为公共模板内容。作品必要资产随作品同步，缓存仍排除；引用清理需同时检查当前作品、历史版本与发布草稿。
