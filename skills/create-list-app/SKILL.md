# 创建列表型应用

适用于 WorkStore 内的白板、笔记、项目等列表型工具。以下为该项目的默认设计约定，用户的新要求优先；不要将这些约定扩展到其他产品。

## 布局与尺寸

- 应用内部采用左右布局；左侧是文档导航，右侧是当前文档工作区。与 WorkStore 全局导航区分开。
- 左侧标题栏与右侧文档标题栏均为 42px，顶边和底边对齐。右侧功能区向上通到顶部，不增加面包屑、切换工具栏或跨越两栏的总标题栏。
- 左侧标题栏依次为 16px 应用图标、14px 标题，不显示标题后的描述。
- 左侧标题栏右侧放小型纯图标折叠按钮，并提供可访问名称和悬浮提示。
- 导航区默认宽 260px；窄窗口可缩为 190px / 164px。列表独立滚动，标题和顶部创建区固定。
- 分组标题“常用”“最近打开”、列表项正文、列表空态均为 14px。描述等辅助文字可以更小，不把画布或编辑器内容字号强制覆盖为导航字号。
- 列表行高 32px，图标与文字间距约 7px，行间距 2px，保持紧凑。

## 折叠与展开

- WorkStore 主导航折叠后的顶部横栏也为 42px，功能图标垂直居中；下方工具高度按 100vh 减去 42px，避免溢出或底部空隙。

- 点击左侧标题栏的折叠按钮后，整个应用内部导航栏隐藏，不保留占位宽度，右侧工作区扩展填满可用空间。
- 折叠时，右侧顶部标题左边显示展开图标；点击后恢复导航栏。展开状态不重复显示这个入口。
- 没有打开文档、空列表或读取出错时，右侧仍保留标题栏和展开入口，避免导航无法恢复。
- 折叠仅改变布局，不清空当前文档、不重置编辑器、不丢失未保存内容。折叠状态持久化不是默认必需项。

## 创建按钮与文档标题栏

- 创建入口固定在各自左侧标题栏下方的“创建”区，不放在主导航或底部。创建区无下边框；水平外间距 9px，分组标题与行的水平内间距 10px，与下方常用/最近列表对齐。
- 创建入口使用加号图标加文字的普通列表行，左对齐、32px 高、14px 常规字重、图文间距 7px；默认透明背景，hover 仅使用与列表一致的浅色背景（#eef2ee），不出现边框或阴影。覆盖组件库 hover 边框时保留键盘 focus-visible 指示。
- 文案为“创建 + 具体对象名”，笔记写“创建笔记”，白板写“创建白板”。空态的创建入口保持同样文案。
- 顶部仅图标创建按钮是旧方案，不再作为默认布局。
- 生成型工具点击“创建”、选择功能/模板或填写参数时只打开内存草稿，不写文档文件、不加入常用/项目/最近；点击“生成”（含分析、裁剪等实际执行入口）并通过必填字段及能力校验后，才创建一条记录并加入最近。生成重入必须去重，连续点击不能创建多个空记录；上传及异步初始化不得覆盖切换后的草稿。
- 生成任务一旦实际提交，失败、取消和部分结果仍保留原记录，便于重试；不删除已有用户文件。草稿参数修改不触发文档同步，已保存作品继续按现有机制保存和同步。
- 无“生成”入口的手工编辑工具（笔记、白板）保留明确创建文档的交互，不强制等待 AI 生成；导入和从完整示例复制已有内容也可立即创建。不得因生成型规则阻止手工编辑保存。
- 创建或草稿转记录过程中显示加载状态，避免重复提交；保留输入法、首击选择、后台任务及正在编辑的数据保护。
- 右侧标题栏保留当前文档标题，可点击重命名；无文档时显示应用名。多页面应用可在中间放 Tab。
- 右侧标题栏右侧默认留空，不加入保存状态、导出或切换工具按钮。导出可以保留在列表更多菜单或编辑器菜单中。保存失败应通过错误提示等方式反馈，不能因隐藏状态区而静默丢失错误。

## 列表交互

- 常用与最近打开来自同一文档集合，以 ID 去重；常用中的条目不在最近打开重复显示。
- 点击条目打开文档并标记选中；再次打开常用文档时定位到常用条目。
- “常用”仅在有可见条目时展示；为空时隐藏整个分组（含标题、占位和间距）。已归入项目的常用条目不计入此分组。最近打开为空时只显示“暂无”，不增加说明段落。
- 更多按钮在 hover 或键盘聚焦时可见，提供设为常用/取消常用、重命名、导出等与应用实际支持能力对应的操作。
- 支持从最近拖入常用时，可用条目图标作为拖动手柄。遵循现有排序规则，不在纯布局任务中顺带改排序。
- 不默认增加底部本地工作空间或文件后缀说明。删除记录与删除文件是不同操作，不能混用。

## 项目分组

- 每个列表型工具使用独立的项目集合；这里的“项目”是工具内的条目分组，不是 WorkStore 的旧项目应用，也不是本机 Git 代码仓库。复用 `src/list-projects/Projects.tsx` 的 `useProjects(toolId)` 与 `ProjectSection`，不要另做一套只保存在组件中的分组。
- 左侧创建区下方按“常用 → 项目 → 最近打开”排列，“项目”位于常用下方、最近打开上方，右侧加号创建项目。项目行仅用闭合/打开的目录图标表达折叠/展开，不显示箭头；右侧 hover/focus 显示创建内容加号和更多菜单，触屏下保持可见；与普通条目同为 32px 行高、14px 正文，hover 仅浅色背景，无边框。项目下条目向右缩进。空项目显示“暂无”，折叠不改变文件或当前编辑器。
- `ProjectSection` 的 `onCreate(projectId)` 接入各工具的创建流程，手工文档保存后通过 `navigation.move(documentId, projectId)` 归入项目；生成型工具保留项目 ID 在草稿中，正式生成记录后才建立成员关系。普通创建重置目标项目，异步任务捕获原项目，不误归到之后切换的项目。创建/归属失败保留文档并显示错误，不删除记录；不支持创建的预览工具不显示项目内创建图标。
- 项目支持创建、重命名、展开/折叠、移除；条目的“…”菜单复用 `navigation.menu(id)` 和 `navigation.handle(key,id)`，提供“移入项目”“新建项目并移入…”与“移出项目”。现有条目无需复制或重新创建即可归类。移除项目须明确说明保留条目，移除后它们按原常用标记回到常用/最近；不要删除项目中的内容文件。
- 每条内容最多属于一个项目。已归类条目仅在项目下展示，不在常用/最近重复出现；保持原常用标记和排序时间，移出可恢复。进入某个项目中的条目时自动展开所属项目；仅切换条目不得重排列表。保留现有行的首次按下选择、尾随 click 去重和输入法保护，项目分组复用工具原来的行渲染，不复制一套事件处理。
- 元数据独立存于 `data/<toolId>/projects.list.json`，通过 `src/list-projects/store.ts` 和 Rust `list_projects` / `update_list_project` 命令读取与修改。项目按稳定 UUID 映射、成员归属按文档 UUID 映射；文件标题不是关联键。移动项目不修改正文、内容文件名、AI 生成快照或文档 ID。
- 更新命令在工作区锁内基于最新文件打补丁，不能回写整份过期快照；保存成功后才显示新归属，失败可见且可重试。未知版本、损坏 JSON、符号链接等拒绝写入，不以空对象覆盖。浏览器预览使用独立的工具命名空间存储，与桌面文件存储区分。
- 项目及成员关系使用现有 GitHub 文件同步。分组移除使用 tombstone，避免旧设备把组复活；成员引用不存在或已移除的组时回落到常用/最近，绝不能因此隐藏文档。不同成员的改动按 ID 三方合并，同一成员并发移入不同组沿用同步历史策略保全各版本；不要用数组整体覆盖或设备时间戳盲目决胜。
- 新工具都接入此通用层。对只有界面预览、尚无内容持久化的工具，可先接入项目入口，但必须说明暂时没有可归类的已保存作品；不可把示例模板冒充用户文档。厂商原版嵌入工具不因左侧有列表就自动改写其内部结构。

## 图标风格

- 沿用白板的简洁青绿色粗线条风格，轮廓清晰，细节少，在 16–20px 下仍可辨识。
- 位图使用真正带透明 alpha 的 RGBA PNG，外部背景透明；不要底色方块、阴影或画出来的棋盘格。物体内部必要的白色填充可以保留。
- 标题栏图标为 16px，与 14px 标题视觉相当；列表应用图标通常为 16–20px。图标容器背景也应透明。
- 资产放在 public/icons/，通过共享图标组件供工具列表、标题和空态复用。
- 白板参考为 public/icons/whiteboard-v4.png 和 src/whiteboard/WhiteboardIcon.tsx。生成或编辑位图时使用可用的 imagegen 技能，不声称使用无法确认的模型版本。

## 本地文档与集成

- 沿用项目 React、Ant Design 和 Tauri/Rust 架构及工具注册方式，按需加载较重的编辑器。
- 每份文档采用独立 JSON 文件，使用业务后缀，如 .whiteboard.json。复用工作目录配置和本地存储接口，支持默认及自定义目录。
- 数据包含稳定 ID、标题、常用标记、创建/打开等时间及业务内容；scene 是白板内容字段，不强加给其他应用。
- 自动保存、切换前处理待保存内容、读取失败提示、重命名和导出沿用存储层机制。浏览器预览存储与桌面文件存储应明确区分。
- GitHub 同步为可选配置，复用已有同步机制，不要求登录或另建用户系统。

## 实施与交付

在 WorkStore 仓库根目录查看对应实现，再按当前应用需要复用：

- src/list-projects/Projects.tsx、model.ts、controller.ts、store.ts、projects.css：项目导航、归属与持久化；src-tauri/src/list_projects.rs：本地文件操作；sync.rs：跨设备验证和合并。
- src/whiteboard/Whiteboard.tsx：布局、列表动作、创建与折叠状态。
- src/whiteboard/whiteboard.css：尺寸和视觉约定。
- src/whiteboard/store.ts：文档存储和保存流程。
- src/whiteboard/WhiteboardIcon.tsx：共享图标组件。

按用户约定，每轮修改完成后重新构建客户端。在仓库根目录执行：

```bash
npm run desktop:build -- --bundles app,dmg
```

macOS 产物位于 src-tauri/target/release/bundle/。构建后更新本机已安装应用，验证签名和安装文件一致性；优先正常退出运行中的应用，无法正常退出时保留旧包并说明重开生效，不强制终止。仅构建当前平台，不声称其他平台已验证。报告实际构建结果；不要把构建通过描述为已经完成交互测试。必要的交互检查覆盖折叠/展开、无文档时恢复导航、创建后自动打开以及当前文档内容保留。项目能力需覆盖已有条目移入/移出、删除分组不删内容、加载/保存失败、缺失分组回落、同名分组不同 ID，以及新设备接入和并发归属合并。
